# 从安装到第一版粗剪

PodCut 运行在自己的电脑上。先用仓库自带的小样检查导入、剪辑、导出和批注，再换成节目素材。首版是实验版，输出用于审听和继续修改。

## 1. 安装与启动

需要 Node.js 22以上、Python 3.12，以及包含 libmp3lame 的 FFmpeg/FFprobe。先安装这些系统工具，再运行：

```sh
git clone https://github.com/Panghugo/podcast-cut.git
cd podcast-cut
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.txt
cp .env.example .env
```

编辑 `.env`，将 `CUT_PYTHON` 改成刚创建的虚拟环境解释器的**绝对路径**，例如 `/你的目录/podcast-cut/.venv/bin/python`。其他路径可以先保留默认值。

```sh
npm run doctor
npm start
```

打开 <http://127.0.0.1:8770>。不需要安装 npm 依赖。离线模型显示“可选”时仍可使用已有转录。首次导入转录依赖可能较慢；若自检超时，可重跑并检查是否有依赖加载错误。

不要把服务暴露到公网。停止服务后项目仍保存在 `data/`，备份时复制整个工程目录。`.env` 和 `data/` 都不进入Git。

## 2. 不花API费用，先检查基本操作

```sh
npm run demo
```

命令会在 `.local/demo/` 生成8秒测试音和配套占位稿；音频没有人声。若目录已有文件，请指定新的输出目录：`npm run demo -- .local/demo-2`。

1. 在网页新建节目，名称可填“操作练习”。
2. 导入 `.local/demo/synthetic-signal.wav`，点击“复制录音到工程”。
3. 选择 `.local/demo/synthetic-transcript.json`，勾选确认稿件与素材共同时间轴对应，点击“绑定转录”。
4. 删除中间的 `B-0002`；保留第一句和第三句，点击“保存修改”。这一步只改方案。
5. 点击“批准当前方案”，再点“生成粗剪音频”。
6. 任务完成后点击审听按钮。应得到约4.42秒粗剪，以及 WAV、MP3、时间线、转录和剪辑记录。
7. 暂停打点、输入意见并保存，再点“回听原版本”检查定位。完成这些操作不调用模型API。

测试音和占位稿只能证明操作流程与时间映射可用，不能证明内容取舍或语音接缝正确。

## 3. 用公开中文语音试用

新建另一个节目，导入 [公开语音目录](../examples/public-speech/) 中的 `source.ogg` 与 `transcript.json`。录音约12秒，来自作者公开发布的普通话对话朗读；来源、许可和校验和在同目录中。

转录是随附的本地ASR结果，文字和说话人未经听辨核准。可以保留全部内容导出，练习对照原声、批注与恢复。这个短小样不是长访谈编辑效果评测；不需要为了演示而强行删除正常内容。

## 4. 配置DeepSeek并自动生成方案

点击“模型设置”，填写：

| 设置 | 值 |
|---|---|
| API地址 | `https://api.deepseek.com` |
| 模型 | `deepseek-flash` |
| 输出方式 | JSON模式 |
| 密钥 | 自己的API密钥 |

模型名可能变化，以服务商当前支持列表为准。密钥可以通过本地 `.env` 的 `CUT_API_KEY` 配置，也可以在界面填写。界面填写的密钥只保存在服务内存，重启后需重新填写；切换地址时不会携带旧密钥。

导入自己的录音和匹配转录，填写剪辑要求。例如：“保留问题提出、具体案例、判断变化和限定条件；删除明确设备调试与无信息重复，正常短回应保留。”先点击“查看调用规模”，再点击“API自动生成方案”。这会向所选服务发送转录文字、剪辑要求及相应意见，按服务商规则计费；自动方案步骤不上传原始音频。

长稿先分段分析，再做全文模型复核。模型输出的句编号、结构和锁定约束会在本地校验。未知编号或锁定冲突会拒绝应用。成功步骤可以复用，失败后用户主动重试可能再次收费，不会自动重试。

## 5. 审阅、批准和返修

按句回听原声，检查问答关系、限定条件、短回应和接缝。可删除、恢复并锁定明确的决定。模型只按句删留，不能改写成录音里不存在的话。自动方案维持原顺序；手动移句须先启用相应设置。

满意后保存并批准，生成一个新的粗剪版本。批注绑定所选WAV及其SHA-256，不会因为后续修改而漂移到别的音频。选择“API只改本段”或“API检查全片”，会得到新草案；仍需重新批准和导出。模型任务成功不会自动将意见标为“已解决”。

## 6. 多轨粗剪

导入各轨后，设置非负起点偏移，确认它们已经在共同时间轴同步。这里是用户声明，不是系统测量；漂移校正须先在其他工具完成。

转录每句填写网页展示的对应 `trackId`，所有时间都使用共同时间轴。导入转录后轨道和偏移固定。批准后导出 `stem-1.wav`、`stem-2.wav` 等同步分轨；逐轨审听时可保持同一播放位置，批注绑定具体音轨。需要混音时，把这些分轨放进音频工作站，从相同零点开始。

首版没有多轨自动转录、选麦、漏音去除或自动混音。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| Python无法启动或版本不对 | 将 `CUT_PYTHON` 指向Python 3.12虚拟环境的绝对路径，重启服务，重跑doctor |
| 转录模型目录未配置 | 先导入已有JSON；本地ASR需要已有faster-whisper large-v3模型目录，不自动下载 |
| 模型返回HTTP错误 | 核对地址、模型、密钥、额度与JSON模式；错误不会自动收费重试 |
| 模型返回未知编号或多余字段 | 下载任务的 `model_rejection.json` 查看失败步骤；当前方案保持原样，修正配置后可显式重试 |
| 工程版本冲突 | 先保留未保存修改，再刷新；后台结果不会覆盖更新后的方案 |
| 转录时间或trackId错误 | 使用当前未剪短素材的时间轴；多轨须指定真实trackId，不套用旧工程ID |
| 新候选仍有想删的重叠语音 | 检查回退与保守恢复记录；共同时间线无法单独删去仍与保留内容重叠的句子 |

外部Codex、Claude或自写程序接入见 [协议与CLI](protocol.md)。当前验证范围和限制见 [开发状态](development.md)。
